# Polluxa LinkedIn Agent Analytics — Data Flow

## End-to-End Data Flow

The analytics pipeline follows this flow:

Source API
↓
Ingestion Service
↓
Leads Staging
↓
Transformation / Modeling
↓
Star Schema
↓
Analytics / BI Layer

## Detailed Flow

### 1. Source API

The source API provides LinkedIn lead/outreach records.

Each record contains fields such as:

- `id`
- `name`
- `job_title`
- `company`
- `status`
- `updated_at`

For the assessment environment, a local mock API is used because no public Polluxa API endpoint/schema was provided.

### 2. Ingestion Service

`app/ingest.py` retrieves records from the source API.

The ingestion service provides:

- Environment-based configuration
- Incremental extraction using `updated_at`
- HTTP 429 handling
- Exponential backoff retries
- Required-field validation
- Idempotent UPSERT using `source_id`
- Dead-letter handling
- Persistent ingestion run metadata

### 3. Staging Layer

Validated source records are stored in:

`leads_staging`

The staging table preserves the source-level record and also stores the raw JSON payload.

The `source_id` acts as the source-system identifier.

### 4. Transformation / Modeling Layer

Records from `leads_staging` are transformed into the analytical Star Schema.

The model contains:

- `dim_agent`
- `dim_company`
- `dim_date`
- `fact_outreach`

Surrogate keys are generated by the database for dimension records.

### 5. Fact Table

`fact_outreach` stores the measurable outreach/lead-level records.

### Fact Grain

One row in `fact_outreach` represents one source LinkedIn outreach/lead record identified by `source_id`.

The fact table references the dimensions through surrogate keys.

### 6. Dimension Tables

#### dim_agent

Stores agent/account-related descriptive information.

#### dim_company

Stores company information associated with the outreach record.

#### dim_date

Provides calendar attributes for analytical date reporting.

### 7. Analytics / BI Layer

The Star Schema is designed to support downstream analytical queries and BI reporting.

Typical analysis can include:

- Outreach volume
- Outreach status
- Company-level activity
- Agent-level activity
- Activity over time
- Recruiter/company performance analysis
